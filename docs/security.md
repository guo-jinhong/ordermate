# 安全说明

## 项目边界

OrderMate 是学习和演示项目。默认账号、默认密码、演示数据与本地 JWT 密钥不能用于生产环境。

## 绝不能提交的内容

- 根目录或 Agent 目录中的 `.env`
- DeepSeek/OpenAI 等模型 API Key
- 真实数据库密码和 JWT Secret
- 完整 JWT、Cookie、会话令牌
- 运行数据库、日志、PID、备份和生产数据导出
- 含密钥或用户隐私的截图和录屏

提交前执行：

```powershell
git status --short
git diff --cached
git grep -n -I -E "OPENAI_API_KEY=.+|sk-[A-Za-z0-9_-]{16,}"
```

示例值和脱敏测试字符串可能产生匹配，必须人工确认每一处。

## 密钥管理

- 本地密钥只放在 `.env`。
- 服务器密钥使用受限权限文件、Secrets Manager 或部署平台 Secrets。
- GitHub Actions 密钥放在 Repository Secrets。
- 如果密钥曾进入公开仓库，应立即吊销并重新生成；只删除当前文件不能消除 Git 历史泄露。

## 网络安全

- 公网只开放 80/443，SSH 仅允许可信来源。
- MySQL、Redis、Agent 调试端口和 Java 调试端口不直接暴露公网。
- 使用 Nginx/Caddy 等反向代理并启用 HTTPS。
- `CORS_ALLOWED_ORIGINS` 必须设置为真实前端域名，不能在生产环境使用任意来源。

## 认证和授权

- Java 后端是最终权限边界，不能只依赖 Agent 提示词。
- 管理接口必须验证管理员角色。
- 订单、地址和购物车操作必须验证资源归属。
- 完整访问令牌不得写入普通日志或模型上下文。

## Agent 安全

- 商品、价格、库存、购物车和订单事实必须来自工具结果。
- 写操作必须经过用户确认，确认令牌应短期、单次并绑定用户。
- 工具参数仍须由后端校验，模型输出不可信。
- 知识库内容不能覆盖系统安全规则或业务授权。
- live 模式录屏前关闭环境变量回显，检查终端和浏览器网络面板。

## 数据安全

- 公开仓库只保留可复现的 SQL 种子数据，不提交运行态 SQLite/MySQL 数据。
- 生产备份应加密、限制访问并定期验证恢复。
- 日志应脱敏密码、令牌、手机号和收货地址。

## 上线最低要求

- 替换 MySQL、JWT、模型服务的所有默认密钥。
- 启用 HTTPS。
- 设置明确 CORS 域名。
- 关闭数据库公网访问。
- 验证自动测试、确认流、资源归属和限流。
- 建立备份、监控、告警和回滚方案。

## 漏洞报告

仓库正式公开后，可在 GitHub 启用 Private vulnerability reporting。不要在公开 Issue 中粘贴真实密钥、令牌或个人数据。
