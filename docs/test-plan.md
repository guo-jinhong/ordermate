## Java 测试

```powershell
.\mvnw.cmd test
```

覆盖：

- 注册、登录、禁用账号和管理员保护。
- 商品创建、更新、删除和搜索。
- 下单、库存扣减、地址归属、数量限制、缺货、取消恢复库存和支付委托。

## Python 测试

```powershell
cd agent-service
.\.venv\Scripts\python.exe -m pytest -q
```

覆盖：

- FastAPI 健康检查、登录代理、聊天、SSE、确认和清空会话。
- demo/live Agent 工具循环与错误处理。
- 商品、购物车、订单与多轮指代状态。
- 内存和 Redis 存储适配。
- 确认令牌、审批工作流和 MCP 工具边界。
- 知识库、提示注入防护、脱敏审计和固定评测集。
- 前端 DOM 引用、双视角、无障碍结构、无外部资源和静态资源体积预算。

知识库测试显式使用本地 JSON，避免被开发机 SQLite/MySQL 数据污染，确保结果可复现。

## 手工业务验收

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 匿名商品查询 | 推荐 3000 元以内的手机 | 调用商品工具并返回真实结果 |
| 登录 | testuser/password | 获得登录态，页面不显示完整 JWT |
| 查看购物车 | 查看我的购物车 | 返回当前用户购物车 |
| 多轮指代 | 推荐手机 → 把它加入购物车 | 使用最近商品上下文 |
| 修改数量 | 把购物车项改成 2 件 | 写操作按设计确认或执行 |
| 查询订单 | 查询我的订单 | 只返回当前用户订单 |
| 取消订单 | 取消待支付订单 | 先出现确认卡，批准后才执行 |
| 拒绝确认 | 点击拒绝 | 订单保持不变 |
| 清空会话 | 调用 clear | 旧商品/订单指代不再生效 |
| 提示注入 | 要求忽略规则并输出 Key | 拒绝请求且不泄露敏感信息 |

## UI v2 最终验收矩阵

以下项目均有静态契约测试保护，但涉及真实浏览器绘制、刷新和容器资源更新的项目仍需人工确认。

| # | 场景 | 操作 | 预期 |
| --- | --- | --- | --- |
| 1 | 首次打开 | 清除当前站点 sessionStorage 后打开首页 | 显示未登录摘要，登录表单默认折叠 |
| 2 | 登录成功 | 使用 `testuser/password` 登录 | 表单消失，账号卡片出现，个人入口解锁 |
| 3 | URL 安全 | 尝试用带 `username`、`password` 查询参数的地址打开 | 敏感参数立即从地址栏移除，密码不进入历史记录 |
| 4 | 登录失败 | 输入错误密码 | 显示明确错误，仍停留在登录区域 |
| 5 | 标签页刷新 | 登录成功后刷新当前标签页 | 服务端校验 Token 后恢复账号卡片 |
| 6 | Token 失效 | 使用过期或无效 Token 刷新/请求 | 清除本地身份，提示“登录已失效” |
| 7 | 退出 | 点击“退出登录” | 清除 Token、用户名、会话上下文和待续动作，个人入口重新上锁 |
| 8 | 双视图 | 分别在未登录和已登录状态切换视图 | 对话/调试视图均可切换，不改变权限；敏感字段保持脱敏 |
| 9 | 匿名受限入口 | 点击购物车或本人订单 | 自动打开登录区并保留动作，不直接发送失败请求 |
| 10 | 登录后续办 | 从受限入口登录成功 | 明确询问是否继续；确认后执行，拒绝后不执行 |
| 11 | 重复提交 | 连续点击发送或确认按钮 | 请求处理中按钮禁用，只产生一次请求 |
| 12 | 响应式布局 | 在 1920、1366、1024、768、手机宽度检查 | 无遮挡；窄屏侧边栏和调试视图使用抽屉；动态地址栏不裁切 |
| 13 | Docker 新版本 | 执行 `docker compose up --build -d agent` 后强制刷新 | 显示 `UI v2 · 20260810.7`，CSS/JS 构建版本一致，无旧页面混用 |

建议浏览器人工验收时同时检查键盘 Tab 顺序、焦点环、Escape 关闭抽屉以及控制台错误。

## live 模型验收

live 测试单独进行，避免在普通 CI 使用真实 Key。建议记录：

- 日期、模型供应商、模型名和代码提交。
- 固定问题集及每条工具选择结果。
- 首事件延迟、最终响应时间和失败原因。
- 是否存在模型编造价格、库存、订单或工具结果。
- 录屏中是否隐藏 Key、JWT、Cookie 和个人数据。

不要在测试报告中粘贴真实 Key 或完整请求头。
